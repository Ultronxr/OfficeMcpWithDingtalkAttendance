# 动态员工与打卡明细查询

## 需求与范围

- `attendance_query` 改用钉钉 `POST /attendance/listRecord`，保留 `start_date`、`end_date` 日期范围入参及包含首尾日期的语义。内部按最多 7 个自然日分段，合并为按工作日升序排列的结果；整体上限沿用可配置的 `Attendance.MaxQueryDays`，默认 31 天。
- 新增可选 `user_id`、`user_name`，有值时二选一；都不填写时沿用配置的默认员工，兼容现有调用。姓名去除首尾空白后精确匹配，重名返回候选 ID、姓名和部门，不自动选择。员工 ID 用于动态查询，不再把固定员工配置当作接口的唯一查询对象。
- 新增 `detail`，可选 `simple`、`full`，默认 `simple`。简略结果保留工作日、员工、打卡类型、计划／实际时间和状态；详细模式附上该条打卡记录的完整上游明细，包括地址、经纬度、设备、Wi-Fi 等实际返回的字段。
- 新增只读 `employee_list` MCP 工具，通过 `/topapi/v2/user/list` 获取分页员工数据，并通过 `/topapi/v2/department/listsub` 遍历应用权限可见的全部部门及子部门。按 `user_id` 去重，返回可直接用于查询的完整 ID、姓名和部门；支持姓名筛选。
- 远程主动打卡和结果核验继续使用已有固定员工及 `/topapi/attendance/getupdatedata` 链路；本次不改变手机脚本、任务编排或自动打卡动作。

## 核心约定

- 保持现有 API Key 认证、令牌缓存、受限并发和整次查询超时。某段失败时标记该段日期失败，保留已完成段；不能把错误转换成无打卡记录。
- 打卡按上游 `workDate` 归属，保留跨午夜的实际时间和同日多条明细。明细查询不再假设每个时段只有一条最终结果，也不自行补造缺卡记录。
- 员工目录短时缓存在内存；上游分页、部门遍历不完整时不缓存为完整目录，不能据此判定姓名不存在或唯一。返回实际员工选择信息，但不在日志、示例、文档或测试中写入真实个人数据。
- 简略模式不携带完整明细；完整模式保留上游字段名与非时间值；按后续确认的 [统一时间规范](time-conventions.md)，所有已知明细时间与摘要统一为可读北京时间，不再返回 time_zone。未返回的字段不自行推断。
- 更新 HTTP 接口、OpenAPI 和两种网关配置示例，让 MCP 同时识别新入参及 `employee_list`。

## 已确认与实现验证依据

用户已确认：员工范围覆盖应用可见的全部部门及子部门；详细模式返回完整打卡明细。默认员工采用兼容现有调用的方案。项目当前没有 `.trellis` 工作流文件，本文件记录本次实现边界。

已通过只读接口核对：`listRecord` 的数据位于顶层 `recordresult`；员工页位于 `result.list`，使用 `has_more` 和 `next_cursor`；子部门结果位于 `result`。只保存响应结构，不保存真实员工和考勤数据。

验收重点为 7 天分段与合并、分段失败／超时、跨午夜归属、简略／完整字段隔离、按 ID／姓名选择、重名处理、部门递归与分页去重，以及原主动打卡核验接口仍可使用。

## 验证结果

- Release 串行构建通过；58 项合成数据测试全部通过，包含分段乱序完成后的合并与并发上限、最大日期边界、部分失败、截止时间、递归分页、目录缓存与重名候选。
- 真实钉钉只读联调通过：完整员工目录、八天跨分段查询、默认员工／指定 ID／指定姓名三种方式，以及 simple／full 返回验证通过；联调仅保存字段结构和条数。
- OpenAPI 已包含四个操作；两份网关 YAML 的工具清单与新参数声明检查通过。2026-09-18 已按用户要求部署后端并更新线上网关，真实公网 MCP 的员工列表、按 ID／姓名查询、八天分段和 simple／full 模式验证通过；用户已完成部署后的测试验收。
