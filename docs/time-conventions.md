# 全项目时间规范

## 已确认目标（2026-09-25）

用户要求所有工具、考勤完整明细、应用日志统一北京时间（UTC+8），通过共用工具类处理；时间自带偏移，不再输出 `time_zone`。原始明细中的时间戳也必须转换为可读字符串，接受这一响应契约变化。本次直接开发，不创建 Trellis 任务；部署和提交另按用户指令执行。

## 强制约定

- 完整时间点统一为 ISO 8601 `yyyy-MM-ddTHH:mm:ss+08:00`，例如 `2026-09-25T09:00:00+08:00`。对外展示到秒，不显示小数、不四舍五入；内部仍保留原始精度用于调度、核验和持久化。
- 纯工作日期保留 `yyyy-MM-dd`；每天重复的作息时刻输出 `HH:mm:ss+08:00`，不能编造日期。所有业务日期、上午判断、随机窗口都按北京时间解释，与进程或手机当前时区无关。
- 后端唯一时间入口为 `Infrastructure/Time/OfficeTime.cs`；HTTP、MVC/OpenAPI、持久化 JSON 和日志共用该工具；对外及日志显示到秒，内部状态单独启用保留精度。手机唯一入口为 `office_time.js`。禁止各功能自行拼接偏移、调用本地时区或直接用 `toISOString()` 作为业务日志时间。
- 明确带 Z 或其他偏移的输入保持实际瞬间再转为 +08:00；已经 +08:00 的时间只统一格式，不重复加八小时。无偏移的合法日期时间明确按北京时间解析，禁止借用宿主本地时区。
- 时间点模型必须使用 DateTimeOffset，不能以 DateTime 或未规范的字符串绕过全局转换器。新增日期时间查询参数必须显式调用 OfficeTime.Parse，不能依赖框架的本地时区绑定。日志消息中的时间插值先用 OfficeTime.Text 格式化，结构化时间属性也经过共用 JSON 转换器。
- 钉钉 `details` 保留字段名和非时间数据，已知时间字段（workDate、planCheckTime、baseCheckTime、userCheckTime、gmtCreate、gmtModified 及对应下划线名称）递归转换为上述完整格式。数字／数字字符串按 Unix 毫秒解释；空值及钉钉无记录的非正时间戳输出 null；非法已知时间返回上游格式错误，不伪造记录。未知字段不凭数值长度猜测时间，扩展上游字段必须同时补充时间字段表与测试。
- MCP 的 `local_execution` 用 `executed_at`、`completed_at`、`screen_on_at`、`app_requested_at` 可读时间替代原 `*_unix_ms` 字段；设备上报协议与内部事实保持 Unix 毫秒，不能把字符串塞进名为 unix_ms 的字段。
- Unix 毫秒是绝对时刻，不能加八小时；延迟、保亮、轮询、超时、加班时长等仍是数量而非时区时间。内部 UTC 时钟可用于瞬间比较和期限计算；写入或展示完整日期时间必须经过工具类。
- 新写入的后端状态日期时间统一 +08:00，并保留七位小数以避免重启后改变过期边界或核验基线；兼容读取已有 Z、+00:00 状态，不批量重写历史文件。手机定时器、持久化计划和设备通信的数值时间戳保持不变，防止升级偏移已经登记的任务。旧日志是历史证据，不重写。
- 上游接口要求的无偏移北京时间参数继续遵守钉钉协议；HTTP 标准 Date/GMT 头、系统日志外层前缀等由对应平台管理，不替换成不合法格式。应用自己的日志正文必须有统一北京时间。

## 工具覆盖与兼容性

| 工具 | 时间规则 |
|---|---|
| attendance_clock_in / attendance_clock_in_status | Task 生命周期、record、local_execution 均为统一可读时间 |
| attendance_automation_set / attendance_automation_status | updated_at、applied_at 使用统一格式 |
| attendance_query | 摘要及 full details 时间统一，删除 time_zone |
| attendance_overtime | 明细、加班时间点、规则时刻统一，顶层及 days 删除 time_zone |
| employee_list | 当前无时间字段；新增字段仍受本规范约束 |

这是公开响应变化：details 时间值由数字或不同格式字符串改为统一字符串／null，local_execution 更名，time_zone 删除。客户端应刷新 OpenAPI/MCP 工具定义。纯日期、记录 ID、时长和设备领取／上报数值协议不改变。

## 新功能检查与验收

- 新增工具必须复用全局序列化、时间工具和本规范，禁止单独决定格式。
- 验证 UTC、其他偏移、无偏移、已是北京时间、数字时间戳、缺卡、跨午夜和精度；断言内部 Unix 时间不变，并验证展示只省略秒后小数、不四舍五入跨秒。
- 同时验证 HTTP 原始 JSON、OpenAPI、旧状态恢复、设备协议、日志及不同宿主时区下的手机规划，防止仅在反序列化后比较而漏掉错误的输出格式。
- 测试只使用合成员工／记录，不访问真实考勤或触发手机动作；开发文档不写入真实凭据、设备状态或个人考勤。

## 本次审计结果

- 修复主动任务及自动开关的 UTC 输出；统一考勤、加班、完整明细、生命周期、日志和本地执行摘要。员工工具没有时间字段。
- 原有日期范围入参、钉钉请求的北京时间日界、按 workDate 归属跨午夜记录、加班时长和任务期限比较均保留原语义；主脚本原本依赖本地时区的窗口及上午判断改为显式北京时间。
- 状态文件通过共用 JSON 选项读写，读取旧 UTC 文件不会偏移实际过期时刻。内部设备上报事实和手机数值状态不迁移；对外展示已经与设备数值协议分离。
- 应用日志通过北京时间 JSON formatter／手机共用时间模块输出。原生系统日志前缀、HTTP 标准时间头、手动建立的周期任务由平台控制，部署文档已说明边界。
- 后端 144 项测试通过（新增 19 项），手机 58 项测试通过；增加秒级显示不四舍五入跨午夜的检查，并验证旧状态精确读写、内部期限保留子秒和旧开关读取不重写文件。手机套件在 UTC 和 America/New_York 宿主下验证窗口与日志，时间工具同时覆盖 Asia/Shanghai。敏感信息扫描未发现真实凭据或非示例 IP。
- 部署预检发现原开关存储每次首次读取都会保存文件，统一格式后会改写旧时间表示；已修正为仅初始化新状态时保存，既有记录读取只加载到内存。专门回归覆盖读取、重复确认不改写，实际设置才按新格式保存。
