# 打卡任务结束后返回手机桌面

## 目标（2026-09-22）

主动远程打卡与被动自动打卡完成后，自动返回手机桌面，减少钉钉留在前台、后续误亮屏再次触发自动打卡的机会。只发送系统桌面请求，不杀后台、不强制停止或退出钉钉、不按返回键清空页面，不额外亮屏，不以客户端界面识别代替钉钉 API 核验。

## 已确认

- 用户确认：本次启动过钉钉就收尾，所有服务端终态都返回桌面，包括成功、已有打卡、失败、过期和超时未确认。
- 主动任务在服务端发现已有上班卡、从未下发手机动作时，不产生新的返回桌面动作。
- 返回桌面不改写考勤是否成功，也不停止既有 API 核验或待补传事实。
- 用户询问熄屏后的可行性，已在测试设备验证：保留现有打开钉钉后保亮 15 秒，不需要为返回桌面一直保亮；保亮结束只是释放保亮，实际熄屏还受系统超时设置影响。

## 补充确认（2026-09-22）

用户明确选择“按这两点实施”：

1. 网络故障一直取不到终态时，打开钉钉 3 分钟后返回桌面，补报／核验继续后台进行。
2. 取得终态时不判断前台应用，直接返回桌面，即使此前已人工切到其他应用。

## 现有链路核对

- 服务端两类 Task 均有终态，设备认证的 `GET /api/devices/{deviceId}/attendance/tasks/{taskId}` 已能查询本设备两类 Task，不需要新增手机查询接口。
- 被动任务由 `office_attendance_queue.js` 拉取并写入最终结果；主动接收器目前在回执提交后不再拉取最终结果，需补齐手机端主动终态查询。
- 共用 `office_device_actions.js` 的 `screen-action` 文件锁覆盖亮屏、请求打开应用和保亮；返回桌面须使用同一锁，防止打断新任务动作。
- 为本次实际启动记录持久化归属标识。新动作开始后，旧任务的晚到结果不能再抢占新动作；升级不扫描旧任务执行历史收尾。
- 采用 Android `ACTION_MAIN`、`CATEGORY_HOME`、`FLAG_ACTIVITY_NEW_TASK` 请求系统桌面，不使用清除任务、强制停止或杀进程。参考 [Android Intent 官方文档](https://developer.android.com/reference/android/content/Intent#CATEGORY_HOME)。日志区分“桌面请求已发送”和“已由系统确认”，不伪造视觉核验。

## 实现边界

- 新增 `office_attendance_cleanup.js`；最近一次动作归属和收尾阶段使用 Android AtomicFile 保存在 `.office-mcp/attendance-cleanup.json`，读写与 Home 均使用原 `screen-action` 锁。
- 最近动作归属只在共用动作入口建立，真实应用启动请求成功后才激活；旧 Task 不自动迁移。归属保存失败停止本次设备动作，避免旧收尾误切新任务；只影响收尾结果的故障不能改写考勤成功状态。
- 被动终态复用既有队列，主动新增手机端只读 Task 查询，不改服务端业务协议和 API 核验规则。无核验 Task 的随机动作仍可按三分钟截止收尾，普通 direct 自身不自动收尾。
- 接收器启动独立本地线程每秒检查终态或 180 秒截止，不联网。系统调度、设备动作互斥及常驻脚本停机可能延迟实际处理，重启后恢复待办。
- Home 前保存 attempting、请求返回后保存 requested；请求异常保存 failed。中断于尝试阶段不盲目重发，以避免旧操作重复抢占界面。日志不把请求接受当作视觉确认。

## 验收方向

- 主动和被动任务在终态后均可发出一次桌面请求，动作未启动、只有亮屏、指令过期等情形不误触发收尾。
- 收尾使用正确系统 Intent，不调用亮屏、杀进程、Back 或启动钉钉。
- 重复结果、常驻脚本重启、旧结果晚到、新动作并发等情况不重复回桌面或中断新任务。
- 返回桌面故障独立记录，不能把有效打卡改成失败，不能阻止事实回报或开关同步。
- 保留原随机窗口、主任务开关、主动打卡动作和统一核验；不新建 Trellis 任务，不自动提交或部署。

## 2026-09-22 熄屏实测

- 在测试设备处于熄屏、钉钉位于任务栈顶部且没有进行中任务时，验证系统桌面请求；具体设备及锁屏配置只保留在本地记录。
- 从 AutoJs6 运行一次诊断脚本，后台等待 30 秒后发送 `ACTION_MAIN + CATEGORY_HOME + FLAG_ACTIVITY_NEW_TASK`，没有调用亮屏、启动钉钉、Back 或杀进程。
- 请求前、请求时、请求后屏幕均保持关闭；系统任务栈顶部变为桌面，钉钉仍保留原任务且变为后台，进程 PID 未改变。
- 这证明当前设备配置支持熄屏请求桌面，不代表任意安全锁屏或其他厂商配置均可保证成功。正式日志仍应称“桌面请求已发送”，不伪造界面识别结果。
- 实测原始证据保存在 Git 忽略的 `artifacts/`；手机诊断入口已经删除，探测过程未修改生产脚本和定时任务。
