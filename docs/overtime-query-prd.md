# 按打卡时间筛选加班日

日期：2026-09-20；基线 `7ca438f`。用户要求新增 MCP 后端只读端点，复用已有考勤范围查询，不新建 Trellis 任务；开发完成后已明确授权部署，未授权本功能提交或 push。

状态：代码及文档已完成，102 项服务端测试通过；2026-09-20 已部署后端并更新网关，公网新工具和考勤对照校验通过。未提交或 push。

## 已确认业务规则

- 使用服务端配置的固定作息，不使用钉钉返回的计划时间计算加班。默认 09:00 上班、18:00 下班、21:00 加班门槛，均按北京时间。
- 有实际 `OffDuty` 下班打卡时间才参与判断。没有下班打卡时间的日期，无论缺卡或其他原因，直接排除；不要求必须存在上班卡。
- 最晚下班时间达到 21:00:00（含）即为加班日。达到门槛后，从 18:00 计算加班时长，例如 21:30 下班计 3.5 小时；不扣除前三小时门槛。
- 同一工作日多条下班记录取最晚实际时间；保留该加班日的全部原始考勤摘要／明细，不仅返回选中的下班卡。
- 跨午夜按钉钉 `workDate` 归属，门槛和下班基准构造于该工作日；例如次日 00:30 的下班卡归属前一工作日，计 6.5 小时。周末不做额外分类，有下班卡即按同一固定时间规则判断。
- 不扣餐休，不按整点取整；用实际时间差计算，秒数为统计基础，小时数展示到小数点后两位。用户没有要求加班审批、法定节假日、倍率或薪资计算。

## 接口与结果

- 新增 `GET /api/attendance/overtime`，MCP operationId 为 `attendance_overtime`。
- 入参复用 `attendance_query`：`start_date`、`end_date` 必填；`user_id`／`user_name` 可选且互斥，均省略时使用默认员工；`detail=simple|full`。日期范围、七天分段、限流并发、超时、姓名消歧、原始明细和身份认证均沿用。
- 内部仅调用一次现有 `AttendanceService.QueryAsync`，在结果上筛选，不复制钉钉传输逻辑、不增加其他钉钉接口、不调用手机动作。
- `days` 只返回符合规则的加班日期，各日保留考勤接口的日期、脱敏员工、时区、全部 records、success 及可用姓名，并增加 `overtime`（正常上下班时间、加班门槛、最晚下班时间、加班秒数／小时数）。
- 顶层返回查询范围、时区、实际规则、`summary`（加班天数及已确认的总加班时长）、`complete` 与 `errors`。查询失败日期放入 `errors`，不会混入加班日期，也不当作确定未加班；汇总只覆盖成功查询的日期。
- 原 `attendance_query` 的数组结构、返回所有日期、钉钉计划时间和原状态均保持兼容。配置的 09:00 上班时刻用于展示规则，不改变原迟到／早退判断。

## 配置与兼容

- 新增 `Overtime` 配置节：`WorkStartTime=09:00`、`WorkEndTime=18:00`、`ThresholdTime=21:00`。限定同一日内顺序为上班 < 下班 <= 门槛，错误配置启动时明确失败。
- 沿用现有启动配置方式，`appsettings.Local.json` 或环境变量覆盖默认值，修改后重启生效。不增加每次调用临时改变统计口径的入参。
- 更新 OpenAPI、两种网关配置示例、HTTP 示例及 README。现有线上网关不会因本地示例变化自动更新；发布时需加入新 operationId 并刷新文档。
- 不修改 AutoJs6 脚本、任务状态管理或真实考勤记录；部署仅增加加班默认配置与办公网关工具项，保留原有业务配置和凭据。

## 验收重点

- 20:59:59 排除，21:00:00 包含，21:30 为 3.5 小时；配置变化实际影响判断且与钉钉计划时间无关。
- 没有下班卡、下班时间为空、仅有上班卡都排除；多条下班卡只计一次且用最晚时间；跨午夜归属与时长正确。
- 加班日保留所有上下班 records，simple/full 隔离、姓名／ID 参数、默认员工、鉴权、七天分段和旧考勤接口兼容。
- 无加班返回空 days 和零汇总；部分／全部查询失败不伪装成完整零加班结果。
- 使用合成测试数据，默认构建目录串行构建；部署验证仅使用只读查询，不触发真实打卡。
