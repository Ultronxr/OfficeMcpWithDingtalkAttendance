# 手机通过公网 HTTPS 直连设备 API

日期：2026-11-12。用户已确认手机独立运行的方向、路由命名和独立设备密钥方案，先授权补充文档及开发，随后明确授权部署。公网入口与手机接收器已部署并完成只读验收；未提交 Git，不创建 Trellis 任务。

## 目标与已确认范围

- 手机连上可访问服务器的互联网后，由唯一 AutoJs6 接收器通过 HTTPS 领取任务、回传结果、同步开关和回应探测，不需要办公电脑、ADB、scrcpy 或手机 ZeroTier。
- 公网根路径固定为 `/office_mcp_device_api/`；例如 `POST https://mcp.example.com/office_mcp_device_api/devices/office-phone/commands/lease`。
- 复用现有公网 HTTPS 域名、证书和入口，由 Nginx 直接代理至内部 `office-mcp`。MCP 的 `/office_common_tools/mcp` 和网关认证保持原样，不新增公网监听端口，不把内部业务端口直接公开。
- 使用现有独立设备认证 `X-Device-Id`＋`X-Device-Key`；每台手机一个设备密钥，只能访问本设备资源。网关 OAuth、网关静态密钥及办公 API Key 不能替代设备凭据；不新增第二重 OAuth。
- 手机主配置使用 `base_url=https://mcp.example.com/office_mcp_device_api`。新公共路径强制 HTTPS、使用系统证书校验、不跟随重定向；密钥不放 URL，不打印连接配置或原始异常。
- 旧的无路径 HTTP／HTTPS 根地址仍可使用内部 `/api/devices/...`，兼容既有 ZeroTier 配置；不自动回落到 HTTP，不同时启动两套领取循环。

## 路径与认证边界

公网前缀只放行下表，Nginx 去掉 `/office_mcp_device_api` 并补回 `/api`，后端继续使用同一组路由、设备认证与存储。

| 方法 | 公网路径（均位于 `/office_mcp_device_api/` 下） | 用途 |
|---|---|---|
| POST | `devices/{deviceId}/commands/lease` | 任务／探测长轮询 |
| POST | `devices/{deviceId}/commands/{taskId}/report` | 已领取动作回执 |
| POST | `devices/{deviceId}/probes/{probeId}/ack` | 本次在线探测应答 |
| POST | `devices/{deviceId}/attendance/executions` | 本地定时执行事实补报 |
| POST | `devices/{deviceId}/attendance/automation/sync` | 自动开关同步及确认 |
| GET | `devices/{deviceId}/attendance/tasks/{taskId}` | 取回本设备任务结果 |

- 未列出的路径返回 404，已列路径使用错误方法返回 405，不代理考勤／员工查询、办公开关设置、创建打卡任务、OpenAPI 或 healthz。
- 手机所有模块仍生成原内部路径，经接收器一个 URL 构建入口转换，避免只改领取地址而漏掉开关、回执、补报或收尾查询。
- 原设备接口不增加“必须来自公网代理”等前提，旧调用方保留原身份与协议；Nginx 不注入设备凭据。后端任务归属、领取凭据校验继续执行。
- 长轮询代理读取超时大于原 25 秒等待，关闭代理缓存、缓冲及上游自动重试；原手机请求超时和退避保持不变。

## 保留的业务行为

继续使用同一份 Task 队列、request_id 幂等、手机持久化去重、动作锁、有效期和官方考勤核验。不改变主动打卡、被动计划、开关、15 秒保亮及终态／三分钟后返回桌面的行为；网络失败只重试原领取或回执，不补做已发生动作。`attendance_device_status` 继续沿当前接收通道验证一次真实往返。
