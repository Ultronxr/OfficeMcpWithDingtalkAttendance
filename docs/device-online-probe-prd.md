# 打卡设备实时在线探测

日期：2026-10-26。用户接受实时往返探测及必要的手机纯通信应答改动，授权开发，随后明确授权部署后端／网关并通过 ADB 更新手机接收器；两轮部署验收后追加授权 Git 提交及推送。不创建 Trellis 任务。

## 目标与边界

- 新增 `attendance_device_status` / `GET /api/attendance/device-status`，探测配置的打卡手机，不接受任意设备或网络地址。
- 每次查询生成独立、不可复用的一次性标识，经实际打卡的已认证长轮询通道送达手机；必须收到对应设备对本次标识的应答才返回 `online=true`。
- `wait_seconds` 默认 10，允许 1～30 秒；超时返回 `online=false`、`status=probe_timeout`，表示本次未证实链路可用，不判断是 ZeroTier、VPN、脚本停止还是接收器忙碌。
- 手机接收器忙于原有动作／回执重试时可能来不及应答；不新增线程、不抢占打卡、不修改重试策略。成功仅证明应答时通信可用，不能保证稍后的网络或打卡成功。
- 不复用最近 60 秒连接标记；探测首次上线保留原接口。用户后续要求从两个自动开关工具移除 `device_online`，实时在线只通过专用探测查询；Task 同名字段仍保持原语义。后续范围见 [自动开关响应职责收敛](scheduled-clock-in-control-prd.md#响应职责收敛2026-10-26)。
- 探测只保存在内存，结束、超时或客户端取消后清理；不创建持久化 Task、不占用动作名额、不访问钉钉、不更新开关，不亮屏或启动应用。

## 协议与兼容

- 新手机领取请求显式传 `supports_probe=true`。仅此类请求可收到 `type=connectivity_probe` 的应答挑战；旧手机仍只收到原命令或 204。
- 原命令优先领取；没有命令时发送待处理探测。探测采用独立的手机应答路由与设备认证，不能经办公 API Key 或其他设备确认。
- 手机识别探测后只回传标识，不进入执行函数或任务去重存储。对旧后端继续使用原命令协议。
- 并发查询各自等待对应标识；未送达、错误、晚到、重放或其他设备的应答不能确认新查询。
- 新接口沿用办公认证、no-store 及统一秒级北京时间；公开 `device_id`、`online`、`status`、`started_at`、`checked_at`、`elapsed_ms`、`wait_seconds`。elapsed_ms 包含等待领取时间，不作为网络 RTT。

## 验收

- 验证真实的内存 HTTP 往返、仅领取不应答、旧在线标记仍为 true 时新探测超时、身份隔离、并发、过期／重放、取消清理和旧手机兼容。
- 验证探测不调用钉钉、不创建任务或修改开关，原打卡命令优先及旧接口回归保持通过。
- 手机脚本测试覆盖纯应答、无设备动作／持久化、格式错误、应答网络失败与原命令路径。
- 同步 OpenAPI、两份网关模板及使用说明；生产部署需同时更新后端、刷新网关并更新／重启接收器，不能以真实打卡验收探测。

## 开发结果

- 探测首次上线已实现新端点、独立内存挑战、认证应答与手机纯通信分支，当时未修改原自动开关端点和 `DeviceCommandStore.IsOnlineAsync`。后续只收敛自动开关响应，不改探测协议或心跳实现。
- 后端首次全量 194 项通过；随后新增“已开始的 25 秒长轮询及时接收挑战”测试并单独通过，合计 195 项（新增 18 项）。手机完整套件 62 项通过（新增 4 项）。
- OpenAPI 已验证公开操作、等待参数范围、响应及时间字段，设备内部接口保持隐藏；两份网关 YAML 均能解析，8 个操作名称一致，新工具为只读 GET。
- 已部署后端与网关，手机仅更新并重启常驻接收器，真实 AutoJs6 编译通过。接收器停止期间新端点返回 `probe_timeout`；恢复新版接收器后，真实公网 MCP 默认参数探测返回 `online=true/status=online`，耗时 495 毫秒。
- 部署后两服务正常运行；自动开关、历史 Task、手机定时任务、CONFIG、计划及收尾状态均保持不变。未触发实际打卡。真实连接信息、备份与验收详情仅存于忽略的本地部署记录。
