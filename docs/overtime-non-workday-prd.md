# 加班查询补齐非工作日出勤

日期：2026-10-08。用户授权直接开发并在完成后部署后端与 MCP 网关，不创建 Trellis 任务；验收完成后追加授权本次 Git 提交及推送。

状态：开发及部署已完成，177 项后端测试通过（新增 33 项）；后端、网关及真实公网 MCP 均完成只读验收。

## 目标与已确认规则

- 工作日沿用配置规则：默认 21:00:00（含）达到门槛，从 18:00 计算时长；不使用钉钉计划下班时间改写该口径。
- 非工作日由钉钉原生报表的 `attendance_rest_days`（休息天数）列判断。当前企业节假日放假也落在该列；不能把星期六、星期日直接等同于休息日，也不能把这个标记进一步伪装成法定节假日分类。
- 休息日及节假日的实际出勤都必须流出：有任意打卡记录即保留该日期及全部 records，不要求达到 21:00，也不要求上下班卡齐全。记录缺少实际时间时同样保留，但标为异常，不声称已经确认实际出勤。
- 缺上班卡、缺下班卡、未知打卡类型和时间顺序异常不隐藏；无法核算的加班时长返回 null，不能用零代替。
- 不以钉钉原生加班列是否为正作为筛选条件：现场样本存在休息并打卡、晚间下班记录但加班列均为零，且原生加班列单位可能为天。

## 本次实施默认细节

用户在两项可选细节提出后直接授权开始开发，按已说明的推荐方案实施：

- 非工作日存在有效上下班卡时，最早 OnDuty 至最晚 OffDuty 为时长；不扣餐休、不取整，内部保留精确秒数，展示小时数保留两位小数。仅能统计首末卡跨度，异常明确输出，不能称为钉钉审批认定时长。
- 日期分类失败／缺失／不明确时，有记录的日期仍进入 days，day_type=unknown、overtime_confirmed=null；保留记录、错误和异常，不计入已确认加班汇总。complete=false，并返回逐日 errors。
- 姓名只解析一次，复用已有考勤查询选中的完整员工 ID 发送报表查询；公开响应仍保持原脱敏规则，离职员工可按 ID 请求，是否可取回由上游实际响应决定。

## 接口与汇总

- 保持 `attendance_overtime` 及五个查询参数，复用一次既有考勤查询；额外读取原生 getattcolumns 与 getcolumnval，不修改原 attendance_query 的响应或设备任务链路。
- 动态发现报表列 ID，通过稳定 alias 识别休息天数，不硬编码企业列 ID。报表值最多 31 天一段，与原始考勤同享单次查询的时间预算；上游业务错误、格式异常和超时不吞掉已获得的记录。
- days 增加 day_type（workday/non_workday/unknown）、overtime_confirmed、inclusion_reason、classification 和 anomalies。未知类型记录完整保留，simple/full 沿用原接口。
- overtime 增加 first_on_duty_at、duration_basis、duration_status；非工作日及未知分类的正常作息／21:00 门槛不适用，输出 null，避免误导。缺卡和不能判定时的秒数／小时数为 null。
- summary 的 overtime_days 统计按工具规则已确认的加班日，包含缺卡但确有非工作日打卡的日期；returned_days、unconfirmed_days、duration_unconfirmed_days、anomalous_days 明示其他情况。总时长只合计已确认且可以计算的日期；duration_complete=false 表示总时长不完整，complete 仅表示考勤及所需分类查询完整。
- 全部时间遵守 [统一时间规范](time-conventions.md)，完整时间点为秒级 +08:00，工作日期为 yyyy-MM-dd，不新增 time_zone。

## 验收与部署

- 覆盖非工作日白天出勤、只有上班／只有下班、未知类型、缺实际时间、多卡、跨午夜、逆序；工作日临界门槛与原有参数／姓名／full 明细兼容。
- 覆盖节假日休息标记、调休工作日标记、列重命名及企业列 ID 不同、列缺失／重复、错误值／日期、部分失败、超时、客户端取消、跨 31 天分段及汇总完整性。
- 测试只使用合成数据；生产验收只查询历史记录，不触发打卡或变更自动打卡开关。部署保留配置、凭据、手机脚本、自动开关和历史 Task，失败回滚程序。
- 更新 OpenAPI、两份网关模板和使用文档；真实采样与部署记录只保存于 Git 忽略的 artifacts／本地文档。

## 实现及上线结果

- 工作日原固定门槛及配置覆盖继续通过回归；非工作日白天完整卡、仅上班卡、仅下班卡、未知类型、无实际时间和逆序记录均有明确结果，异常日期不被隐藏。
- 原生休息列按 alias 动态发现，覆盖列重命名、不同企业 ID、缺失／重复元数据、错列、重复／非法／越界日期、空值及不明确值。分类失败保留记录，超时与客户端取消分别处理，长范围报表分段保留已完成分类。
- HTTP 原始 JSON 和 OpenAPI 均验证 nullable 时长、分类及异常字段；原考勤接口、姓名解析、完整明细、任务／开关时间契约保持兼容，所有完整时间仍为秒级 +08:00。
- 线上对同一历史范围的原考勤和新加班 full 结果进行对照，白天非工作日完整卡及单卡均返回，records 全量一致；单卡时长为 null，汇总的 duration_complete=false。
- 后端产物逐文件哈希一致，后端及网关均运行正常；配置、凭据、原 Task 与自动打卡开关哈希一致，验收未创建打卡或设置开关。详细证据及备份只在忽略的本地部署记录中保留。
