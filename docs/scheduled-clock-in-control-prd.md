# 被动自动打卡远程开关

## 目标与已确认范围（2026-09-21）

通过 MCP 远程关闭／开启固定手机的被动随机自动打卡，适用于请假前关闭、返岗前开启。控制状态持久化，重启后保留。

用户已确认：

1. 关闭同时禁止主任务后续规划和已登记但未执行的随机子任务；主动远程打卡照常使用。
2. 开启从下一次原定主任务触发时恢复，不立即打卡、不补建当天计划。
3. 手机断网期间沿用最后收到的开关；远程关闭必须等待手机同步确认才能认定生效。

保留 AutoJs6 周期主任务和原有日期／星期编排，不删除或重建它。关闭通过脚本运行门禁实现；只取消该入口登记的一次性子任务。已开始的动作不能撤回，其事实回报及钉钉 API 核验继续完成。不增加请假日历、自动恢复时间、外部通知，不改变原随机窗口和主动打卡规则。

## 接口与持久化

- `GET /api/attendance/automation`，MCP `attendance_automation_status`：查询服务端期望状态、版本、手机最后确认状态和时间、是否待同步、设备在线状态。
- `POST /api/attendance/automation`，MCP `attendance_automation_set`：显式 `enabled`，UUID `request_id`，`wait_seconds` 默认 45、范围 0～60。相同请求重试不再次修改开关；相同 UUID 不允许更换 enabled。已被后续请求覆盖的旧重试只返回当前状态和原请求版本，不恢复旧设置。
- 设置已确认返回 200；仍待手机确认返回 202。请求响应携带本次请求版本及是否已被后续设置覆盖；不能把“服务端已保存”描述为“手机已关闭”。
- 手机专用 `POST /api/devices/{deviceId}/attendance/automation/sync` 使用既有设备认证；仅固定绑定设备可读写确认信息，接口不进入 MCP/OpenAPI。
- 服务端动态开关与请求去重记录存放于设备状态目录的独立子目录，文件原子替换并使用单实例锁，不写静态配置、不混入打卡 Task、不产生设备动作。
- 初始服务端状态为开启、版本 0，手机尚未同步时为未知；首次安装手机模块且无本地状态时沿用原启用行为。持久化文件损坏必须显式报错，不能悄悄恢复默认开启。
- 状态包含最近一次关闭的版本。手机跨过多次开关后首次恢复连接，即使最新状态已经开启，也必须取消关闭前留下的旧计划。

## 手机执行与同步

- 新增共用控制模块，使用原子文件和跨引擎锁保存手机状态。
- 常驻接收器同步期望状态，成功落盘且处理待执行计划后才上报确认。每轮同步失败独立记录，不阻塞原远程回执、主动打卡和本地核验补报。
- 随机主任务规划、子任务执行与开关应用共用控制锁，避免“确认关闭后仍从旧开关发起动作”。已进入执行的动作完成并释放锁后才允许确认关闭。
- 关闭只移除入口自身计划中的 pending／creating 子任务，验证任务 ID 对应的脚本路径、一次性类型和原计划时间，不扫描删除其他任务；保留取消的历史计划。类型与时间使用 AutoJs6 [TimedTask.isDisposable/getMillis](https://github.com/SuperMonster003/AutoJs6/blob/master/app/src/main/java/org/autojs/autojs/timing/TimedTask.java)；周期任务即使复用历史 ID 也不误删、不被旧计划遮蔽。
- 开启仅更新状态，不直接运行主脚本、不新建计划。direct 手动动作不受远程开关影响；原 `CONFIG.enabled` 仍是本机上层禁用配置。
- 没有模块、状态无法读取或锁获取失败时，随机自动任务停止并记录错误，防止无法确认关闭状态却继续执行；网络断开不影响读取上次状态。
- 手机日志记录版本、开关、取消数量和跳过原因，不记录凭据或员工信息。

## 验收

- 鉴权、设备绑定、enabled 缺失／类型错误、UUID／等待参数校验，OpenAPI 与两种网关配置一致。
- 状态跨服务重启保留；相同请求幂等、冲突拒绝、旧请求重试不覆盖新状态、过时手机确认不使新设置变成已生效。
- 关闭主任务不建计划，已登记子任务取消；开启不补建，下一次主任务按原窗口登记；快速关闭再开启、离线跨版本同步不会复活旧计划。
- 开关应用与规划／执行并发受同一门禁保护；原周期任务、主动动作、核验队列和状态查询不退化。
- 使用合成设备／内存网络进行服务端与脚本测试。本次开发不操作生产开关，不触发真实打卡；部署另按用户指令执行。
